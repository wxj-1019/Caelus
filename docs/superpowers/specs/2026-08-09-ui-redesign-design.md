# Caelus UI 重构设计规格

**版本**: 1.0  
**日期**: 2026-08-09  
**状态**: 待实现  
**作者**: zenjiro  

---

## 1. 背景与目标

### 1.1 当前状态

Caelus v1.7.0 是基于 C# WinForms 的 Windows 桌面游戏优化工具。当前 UI 采用深色科技面板风格，包含切角卡片、细描边、琥珀金强调色、网格纹理和自绘环形仪表。功能完整，但存在以下系统性问题：

- **信息平铺而非分层**：所有状态同等显眼，用户需自行判断优先级
- **装饰喧宾夺主**：环形仪表占概览页 40% 面积，传达的信息却最弱
- **说明文案全部展开**：诚实但阅读负担重，高频页面需滚动一屏以上
- **状态语义模糊**：金色同时承担品牌、选中态、强调态，用户难以快速识别系统状态
- **基础能力缺失**：日志页无空态、无过滤、无搜索；设置页出现未适配主题的原生控件

### 1.2 重构目标

| 目标 | 说明 |
|------|------|
| **Apple 式体验** | 清晰、克制、内容优先、动效有意义、可访问性完整 |
| **双层信息架构** | 普通玩家默认简洁，高级用户按需展开诊断与控制 |
| **状态语义化** | 颜色只表达状态含义，品牌色不承担状态职责 |
| **技术可持续** | 迁移到 WPF + MVVM，建立可维护的设计系统 |

### 1.3 成功标准

- 用户打开应用后 3 秒内能理解系统状态
- 普通用户完成核心操作（查看状态、切换模式、启动游戏）无需阅读说明
- 高级用户能在 2 次点击内找到任意诊断信息
- 所有控件（包括输入框、滚动条、下拉菜单）完全适配当前主题
- 支持减少动态效果模式，动画帧率 ≥ 60fps

## 2. 设计原则

本方案融合以下前沿设计理念：

| 原则 | 应用方式 |
|------|----------|
| **Clarity（清晰）** | 文字可读、图标精确、装饰最小化、负空间突出重要内容 |
| **Deference（内容优先）** | UI 帮助用户理解内容，但不与内容竞争；chrome 退居其次 |
| **Depth（层次）** | 用柔和材质、透明度和阴影建立空间感，而非边框切割 |
| **Calm Technology** | 系统只在需要决策时打扰用户，状态摘要代替持续数据噪声 |
| **Progressive Disclosure** | 先给结论，再给证据，最后给控制权 |
| **Spatial UI** | 用层级关系组织界面，减少碎片化边框 |
| **Adaptive Density** | 普通模式舒适留白，专业模式提高信息密度 |
| **Meaningful Motion** | 动效表达因果、进度和空间位置，支持减少动态效果 |
| **Semantic Color** | 颜色只表达状态、风险和操作意义 |
| **Trustworthy Feedback** | 每次优化说明影响范围、进度、结果和撤销能力 |

## 4. 组件规范

### 4.1 按钮

| 类型 | 背景 | 文字 | 边框 | 用途 |
|------|------|------|------|------|
| Primary | Brand / Info | White | 无 | 主要操作（保存、启动优化） |
| Secondary | Surface | Text-primary | 1px Border | 次要操作（取消、查看详情） |
| Ghost | Transparent | Info | 无 | 轻量操作（展开、收起） |
| Danger | Danger / 10% opacity | Danger | 无 | 破坏性操作（清除、删除） |

**状态**：Hover 时背景加深 8%；Active 时加深 12%；Disabled 时透明度 40%。

### 4.2 开关（Toggle）

- 尺寸：宽 44px，高 24px，圆角 12px
- 滑块：直径 20px，白色，带 `shadow-sm`
- 开启：背景 Success 色，滑块右侧
- 关闭：背景 `text-tertiary` 色，滑块左侧
- 过渡：200ms ease-out

### 4.3 卡片（Card）

- 背景：`surface`
- 边框：1px `border`
- 圆角：`radius-md`
- 内边距：`space-md`
- 阴影：`shadow-sm`
- Hover 时：阴影升级为 `shadow-md`，边框颜色加深

### 4.4 输入框

- 背景：`surface`
- 边框：1px `border`
- 圆角：`radius-sm`
- 内边距：`space-sm` `space-md`
- 聚焦时：边框颜色 Info，外发光 2px Info 20% opacity
- **必须完全自绘或使用 WPF 原生样式，禁止出现未适配主题的原生滚动条**

### 4.5 导航（NavRail）

- 宽度：200px（普通模式）/ 64px（紧凑模式）
- 背景：`background`
- 选中项：背景 Info 10% opacity，文字 Info，左侧 3px Info 竖条
- 未选中项：文字 `text-secondary`
- Hover 时：背景 `surface-raised`

### 4.6 分段控件（Segmented Control）

- 用于模式选择（常规/竞技/自定义）
- 背景：`surface-raised`
- 圆角：`radius-sm`
- 选中项：背景 `surface`，文字 `text-primary`，带 `shadow-sm`
- 未选中项：文字 `text-secondary`
- 过渡：200ms ease-out

```
│  Rail   │ ┌─────────────────────────┐   │
│         │ │ ✓ 游戏环境已准备好      │   │
│         │ │   竞技模式已应用        │   │
│         │ │              [查看详情] │   │
│         │ └─────────────────────────┘   │
│         ├───────────────────────────────┤
│         │ ┌────┐ ┌────┐ ┌────┐         │
│         │ │62° │ │144 │ │8.4 │         │
│         │ │GPU │ │FPS │ │ GB │         │
│         │ └────┘ └────┘ └────┘         │
│         ├───────────────────────────────┤
│         │ ┌─────────┐ ┌─────────┐       │
│         │ │最近活动 │ │快速诊断 │       │
│         │ │         │ │         │       │
│         │ └─────────┘ └─────────┘       │
│         └───────────────────────────────┘
```

#### 状态结论规则

| 条件 | 结论文案 | 颜色 | 图标 |
|------|----------|------|------|
| 守护开启 + 游戏运行中 | 游戏优化中 | Success | ✓ |
| 守护开启 + 游戏未运行 | 游戏环境已准备好 | Success | ✓ |
| 守护关闭 | 守护已关闭 | Warning | ○ |
| 检测到问题 | 需要注意 / 需处理 | Warning / Danger | ⚠ / ✕ |

#### 关键指标

- GPU 温度：显示数值 + 进度条，正常 < 75°，警告 75-85°，危险 > 85°
- 目标帧率：显示数值，无状态色（仅信息）
- 已用内存：显示数值 + 进度条，正常 < 80%，警告 80-90%，危险 > 90%

#### 交互

- 「查看详情」展开完整状态面板
- 「快速诊断」默认收起，点击展开显示 GPU 驱动、后台进程、反作弊状态
- 模式切换通过顶部 Segmented Control，不遮挡内容

## 6. 动效规范

### 6.1 原则

- 动效表达因果、进度和空间位置
- 所有动画统一节奏，避免不同组件各自运动
- 支持「减少动态效果」模式，尊重系统设置

### 6.2 标准动效

| 场景 | 类型 | 时长 | 缓动 | 说明 |
|------|------|------|------|------|
| 页面切换 | 淡入 + 位移 | 250ms | ease-out | 新页面从右侧 20px 处淡入 |
| 卡片展开 | 高度展开 | 300ms | ease-out | 从原位置展开，保持空间连续性 |
| 状态更新 | 数字滚动 | 400ms | ease-out | 指标数值平滑过渡 |
| 开关切换 | 滑块移动 | 200ms | ease-out | 跟随手指/鼠标 |
| 模态框 | 缩放 + 淡入 | 250ms | ease-out | 从中心 95% 缩放至 100% |
| 成功反馈 | 图标弹跳 | 400ms | spring | 完成后短暂反馈 |

### 6.3 减少动态效果模式

- 所有动画时长 × 0.5 或直接禁用
- 页面切换改为直接替换
- 数字更新改为直接跳变
- 保留透明度渐变（非位移动画）

## 8. 技术方案

### 8.1 技术选型

| 方案 | 评估 | 结论 |
|------|------|------|
| **WPF + MVVM** | 兼容现有 .NET Framework；XAML 统一定义设计系统；动画、主题、DPI 原生支持；迁移风险最低 | **推荐** |
| WinUI 3 | 更现代的 Fluent Design，但 Windows App SDK 部署复杂，对现有系统 API 调用兼容性待验证 | 备选 |
| 继续 WinForms | 自绘成本高，主题覆盖不全，动画能力有限 | 不推荐 |

```
│  ┌─────────┐  ┌─────────┐          │
│  │  Views  │  │ViewModel│          │
│  │ (XAML)  │  │  (C#)   │          │
│  └────┬────┘  └────┬────┘          │
│       │            │                │
│       └────────────┘                │
│              │                      │
│              ▼                      │
```

### 8.3 迁移策略

- **保留**：现有监控、优化、日志、进程识别核心逻辑（Domain 和 Infrastructure 层）
- **重写**：Presentation 层（WinForms → WPF）
- **新增**：Design System 资源字典、ViewModel 层

### 8.4 关键实现

- **主题系统**：WPF ResourceDictionary，支持运行时切换
- **动画**：Storyboard + VisualStateManager
- **DPI**：Per-Monitor V2，WPF 原生支持
- **托盘**：保留现有 NotifyIcon 逻辑，通过 WPF 互操作

## 9. 分阶段实施

| 阶段 | 内容 | 交付物 | 验收标准 |
|------|------|--------|----------|
| **Phase 1** | 设计系统 + 概览页 | WPF 项目骨架、颜色/字体/间距资源、概览页完整实现 | 概览页在浅色/深色主题下渲染正确，动画流畅，DPI 适配正常 |
| **Phase 2** | 游戏库 + 优化策略 | 两个页面完整实现 | 空态、拖放、Segmented Control、说明分层正常工作 |
| **Phase 3** | 日志 + 设置 + 其余页面 | 所有页面迁移完成 | 日志过滤/搜索/空态正常，设置页无原生控件泄漏 |
| **Phase 4** | 动效 + 可访问性 | 动效完善、可访问性支持 | 减少动态效果模式生效，键盘导航完整，屏幕阅读器可识别 |

## 10. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| WPF 对现有系统 API 调用兼容性 | 功能异常 | Phase 1 优先验证进程监控、优先级调整、托盘图标三项核心系统调用在 WPF 宿主下行为一致；保留 WinForms 版本作为回退 |
| 动画性能不足 | 卡顿 | 使用硬件加速；复杂动画用 CompositionTarget.Rendering 优化 |
| 用户习惯深色主题 | 抵触 | 深色主题作为可选；默认浅色但保留切换入口 |
| 开发周期过长 | 延迟交付 | 分阶段交付，每阶段可独立验收；核心逻辑复用减少重写 |
